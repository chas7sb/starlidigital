These are the actual 22 source/test files from the effective dashboard/worker runtime directory, plus three dependency provenance manifests. The original archive SHA256 is `a73ef09b57924a47958649d4b9c1c8f43bb0908a81b11426f580cce4ee6c6715`; original source hashes are in `extraction-manifest.json`. No Pi auth profiles, provider vault, keys, sessions, transcripts, production environment file, or dependency tree were copied.

The new standalone manifest and lockfile pin the installed Pi API generation at `@earendil-works/pi-coding-agent`, `pi-agent-core`, and `pi-ai` version1.5.0. The package also declares the actual TypeScript runner, MCP SDK and browser compiler dependencies. Install from this directory with `npm ci`, then install `requirements.txt` into the dashboard Python environment. Installed dependencies are not part of the source package.

Set `STARLI_RUNTIME_CODE_DIR` to this directory, not the platform root. Set `STARLI_PYTHON_BIN` and `STARLI_NODE_BIN` to the selected executables, and `STARLI_STATE_DIR` to a fresh absolute private instance state directory. `runtime-contract.json` lists the full installer contract. SDK imports resolve the installed packages; no production absolute paths remain in the runtime source. `STARLI_DASHBOARD_ROOT` is optional in the standard repository layout and required if relocating this extension independently.

Provider catalog, login and inference use line-delimited JSON over private stdin/stdout IPC. Operators supply their own accounts/keys through the dashboard. The optional managed fallback reads only an explicitly configured `STARLI_MANAGED_ENV_FILE`; it never reads the production server's environment file. The native registration utility requires an explicit existing local admin email through `STARLI_REGISTER_ADMIN_EMAIL` and is not run automatically.

Vault access uses the dashboard's exact `require_private_file` validator for both the master key and encrypted accounts database. Windows requires a current-user-owned protected private DACL; broad inherited state is rejected without repair. POSIX retains owner, mode, symlink and single-link checks. Lock/home directories are created through the same privacy helper. Exclusive locks use stdlib `msvcrt` on Windows and `fcntl` on POSIX with a bounded wait; lock files reject reparse points and multiple links. Credential refresh remains an encrypted SQLite transaction and will not resurrect credentials removed during inference.
