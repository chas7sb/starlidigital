# Native integrations catalog

Mount `IntegrationsCatalog.svelte` with companyId, actorId and accessSignal; handle close and denied {status}. The client reads only GET `/api/v1/starli/companies/{company}/automations/integrations/catalog` with native session bearer and no-store. It requires `version: starli.integration-catalog.v1`, exact companyId and validated connector/action/status fields, and rejects late session/access responses.

The source contains445 connector listings and3369 action definitions extracted from installed metadata. A listing does not mean it can execute. The UI distinguishes Available, Connect account, Needs platform setup and Not executable yet using server-derived executionStatus. Missing per-action availability remains Not executable yet, even if its parent connector has reviewed support. There are no Create/Run controls and no inferred connection endpoints. Credential types, package/vendor identifiers and internal source IDs are not rendered. The source metadata is not duplicated into the frontend bundle; the native company endpoint owns authoritative availability overlays.

One searchable list/detail interface covers providers/actions. Initial lists are bounded to60 cards with Show more. On390px the selected detail is presented above the listing. Access/session changes clear all state. Metadata descriptions are escaped plain text, with markup removed and private engine branding omitted.

`integration-catalog.test.cjs`: exact native GET transport, company/version/status validation, late session/abort rejection, safe plain text and strict TypeScript pass. `verify-browser.cjs`: actual component against the complete extracted445/3369 fixture passes provider/action search, status clarity, no execution controls, availability filters, hidden internal IDs,390px and access clearing. Every request is intercepted; zero live writes/browser errors. Root owns the additive production catalog endpoint and reviewed capability overlay.
